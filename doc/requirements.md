# WorkDrive 요구사항 정의서

## 1. 프로젝트 개요

WorkDrive는 사용자가 웹에서 파일을 업로드, 다운로드, 조회, 공유할 수 있는 클라우드 파일 관리 시스템이다.

## 2. 요구사항 목록

| 식별자(ID) | 그룹(분류) | 요구사항 상세 내용 | 우선순위 |
|---|---|---|---|
| F-001 | 회원 관리 | 사용자는 이메일과 비밀번호로 계정을 생성한다. | High |
| F-002 | 로그인 | 사용자는 가입한 계정으로 로그인한다. | High |
| F-003 | 파일 관리 | 사용자는 파일을 업로드한다. | High |
| F-004 | 파일 관리 | 사용자는 저장된 파일을 다운로드한다. | High |
| F-005 | 파일 조회 | 사용자는 저장된 파일 목록을 확인한다. | Medium |
| F-006 | 파일 공유 | 사용자는 다른 사용자에게 파일 공유 권한을 설정한다. | Medium |
| N-001 | 성능 | 시스템은 파일 목록을 3초 이내에 출력한다. | High |
| N-002 | 보안 | 시스템은 사용자 비밀번호를 암호화하여 저장한다. | High |
| N-003 | 보안 | 시스템은 권한이 없는 사용자의 파일 접근을 제한한다. | High |
| N-004 | 사용성 | 사용자는 복잡한 절차 없이 파일 업로드 기능을 사용할 수 있다. | Medium |
| N-005 | 가용성 | 시스템은 안정적으로 파일 관리 서비스를 제공한다. | Medium |
| I-001 | 사용자 화면 | 시스템은 로그인 화면을 제공한다. | High |
| I-002 | 사용자 화면 | 시스템은 파일 업로드 화면을 제공한다. | High |
| I-003 | 사용자 화면 | 시스템은 파일 목록 조회 화면을 제공한다. | High |
| I-004 | 사용자 화면 | 시스템은 파일 공유 설정 화면을 제공한다. | Medium |
| Q-001 | 신뢰성 | 시스템은 파일 업로드 실패 시 오류 메시지를 출력한다. | High |
| Q-002 | 유지보수성 | 시스템은 회원 관리와 파일 관리 기능을 분리하여 개발한다. | Medium |
| D-001 | 개발 환경 | 개발자는 GitHub를 사용하여 문서를 관리한다. | High |
| D-002 | 데이터 관리 | 시스템은 사용자 정보와 파일 정보를 데이터베이스에 저장한다. | High |
